How Flooding Algorithm Works

Flooding is a straightforward data transmission and routing technique where every incoming packet is sent out on every outgoing line except the one it arrived on.

Core Rules of Flooding:
  • 1. Broadcast to Neighbors: Source injects packet to all connected 1-hop neighbors.
  • 2. Reverse Path Filter: Nodes never echo a packet back onto the exact link it arrived from.
  • 3. Hop-Count / TTL: Every packet carries a Time-To-Live (TTL) decremented at each hop. If TTL drops to 0, the packet is discarded.
  • 4. Duplicate Filtering: Nodes remember previously seen (Source, Seq#) pairs to discard duplicates and prevent infinite looping.

Strengths & Weaknesses

✅ Advantages
  • Extremely robust against node failure
  • Always finds shortest path
  • No routing table computation required
⚠️ Limitations
  • Generates massive duplicate overhead ("Broadcast Storm")
  • Consumes high bandwidth & battery
  • Requires duplicate caches or strict TTL

Connection to DSR Protocol

In Dynamic Source Routing (DSR), flooding is selectively used during the Route Discovery phase (RREQ packets). Instead of blindly flooding data payload, DSR floods tiny route request packets to discover the optimal path, which is then cached for unicast transmission.
