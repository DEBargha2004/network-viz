TCP Tahoe Congestion Control

Introduced in 1988 by Van Jacobson, TCP Tahoe was the seminal algorithm that saved the early internet from collapse by implementing AIMD (Additive Increase / Multiplicative Decrease).

The 3 Phases of TCP Tahoe:
  • 1. Slow Start: Begins with cwnd = 1. For every ACK received, cwnd increases by 1 MSS (doubling each RTT: 1, 2, 4, 8...). Runs while cwnd < ssthresh.
  • 2. Congestion Avoidance (Additive Increase): Once cwnd ≥ ssthresh, exponential growth stops. The window grows linearly by +1 MSS per RTT (+1/cwnd per ACK received).
  • 3. Loss Reaction (Multiplicative Decrease): On packet loss (Timeout or 3 Duplicate ACKs):
    • ssthresh ← max(2, ⌊cwnd / 2⌋)
    • cwnd ← 1 (Always resets all the way to 1!)
    • Re-enters Slow Start.

Tahoe vs TCP Reno

TCP Tahoe (1988)
  • Fast Retransmit on 3 Duplicate ACKs
  • No Fast Recovery
  • Always resets cwnd = 1 on any loss
  • Severe throughput penalty from Slow Start restart
TCP Reno (1990)
  • Fast Retransmit on 3 Duplicate ACKs
  • Fast Recovery: sets cwnd = ssthresh + 3
  • Does NOT reset to 1 on 3 Dup ACKs
  • Skips Slow Start and resumes Congestion Avoidance directly!
